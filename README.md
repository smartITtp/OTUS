# OTUS
Проектная работа SQL курса в OTUS

Информационная система магазина электроники

1. Описание проекта

Система управляет:
- Клиентами и их заказами
- Сотрудниками и их обработкой заказов
- Товарами, их категориями и поставщиками
- Корзинами и списками желаемого
- Скидками и отзывами
- Методы оплаты и доставка

Проект реализован на PostgreSQL с использованием:
- Таблиц с ограничениями целостности
- Индексов для оптимизации поиска
- Хранимых процедур и функций
- Триггеров для автоматического обновления данных
- Представлений для отчетности

Структура базы данных

Основные таблицы
- **Customers** — клиенты
- **Employees** — сотрудники
- **Suppliers** — поставщики
- **Categories** — категории товаров
- **Products** — товары
- **Orders** — заказы
- **Order_Items** — позиции заказов
- **Cart / Cart_Items** — корзины и товары в них
- **Product_Reviews** — отзывы на товары
- **Payment_Methods** — методы оплаты
- **Shipping** — данные доставки
- **Discounts / Product_Discounts** — скидки на товары
- **Wishlist / Wishlist_Items** — списки желаемого

Связи
- Один клиент может иметь несколько заказов ('1:M') 
- Один заказ может содержать несколько товаров ('1:M') 
- Связь товары↔скидки реализована через 'Product_Discounts ('M:N')'
- Связь товары↔список желаемого реализована через 'Wishlist_Itens ('M:N')' 


Индексы
- 'idx_customers_email' — поиск клиента по email 
- 'idx_orders_customers' — быстрый поиск заказов клиента 
- 'idx_products_category' — поиск товаров по категории 
- 'idx_order_items_order' — join Order_Items → Orders 
- 'idx_cart_items_cart' — join Cart_Items → Cart

Хранимые процедуры и функции


Процедуры
- 'create_order(customer_id, employer_id, payment_method_id, shipping_id, items_json)' — создание заказа с проверкой наличия товаров и подсчетом цены 
- 'add_to_cart(customer_id, product_id, quantity)' — добавление/обновление товара в корзине 
- 'update_order_status(order_id, status)' — изменение статуса заказа с проверкой финальности 
- 'add_product_stock(product_id, quantity)' — добавление товара на склад 
- 'apply_discount_to_product(product_id, discount_id)' — применение скидки к товару 


Функции
- 'validate_order_items(items_json)' — проверка наличия товаров и их количества 
- 'get_product_final_price(product_id)' — расчет цены с учетом скидок 
- 'is_order_final(order_id)' — проверка финальности заказа 


Триггеры
- 'tr_order_items_after_insert' → уменьшение stock при добавлении заказа 
- 'tr_orders_before_update' → автоматическое обновление даты изменения заказа 


Оптимизация производительности
- Использование индексов для ускорения поиска и join-ов
- Агрегаты и представления ('v_orders_summary', 'v_top_products', 'v_product_rating') для быстрого получения отчетов 
- Проверки наличия товаров в 'validate_order_items' до вставки заказов 
- Хранимые процедуры позволяют минимизировать сетевые запросы и держать логику на стороне БД

Более подробное описание функций и процедур, а также методы оптимизации

1. Хранимые процедуры и функции
create_order()

Назначение:
Создание нового заказа с валидацией, расчетом цен и автоматическим уменьшением остатков на складе.

Как работает:

1. Вызывает функцию validate_order_items для проверки:

-существования товаров
-достаточного количества на складе

2. Создаёт запись в таблице Orders

3. Добавляет позиции в Order_Items

4. При вставке в Order_Items автоматически срабатывает триггер tr_order_items_after_insert, уменьшающий Products.stock

5. Цена каждой позиции вычисляется функцией get_product_final_price

Для чего:
Вся бизнес-логика создания заказа вынесена на сторону БД, что:

1. предотвращает неконсистентные данные

2. исключает создание заказов с недоступными товарами

3. уменьшает количество сетевых запросов из приложения

---

add-to_cart()

Назначение:
Добавление товара в корзину клиента.

Особенности реализации:

1. Корзина создаётся автоматически при первом добавлении товара

2. Используется ON CONFLICT DO UPDATE для увеличения количества товара

Для чего:
Позволяет безопасно и эффективно управлять корзиной без предварительных проверок на стороне клиента.

---

update_order-status() 

Назначение:
Обновление статуса заказа с контролем бизнес-логики.

Использует функцию:
is_order_final(order_id)

Логика:

1. Если заказ уже в финальном статусе (Доставлен, Отменен) — изменение запрещено

2. Проверяется допустимость нового статуса

3. Все изменения логируются в Order_Status_History

Для чего:

1. Исключает некорректные переходы статусов

2. Обеспечивает аудит изменений заказов

3. Позволяет отслеживать историю жизненного цикла заказа

---

add_product_stock()

Назначение:
Увеличение количества товара на складе или создание товара при его отсутствии.

Для чего:
Используется для складских операций и пополнения ассортимента.

---

apply_discount_to_product() 

Назначение:
Применение скидки к товару.

Особенности:

1. Проверяет существование товара и скидки

2. Обновляет таблицу связей Product_Discounts

3. Сохраняет вычисленную цену в price_with_discount

Для чего:
Позволяет управлять скидками централизованно и использовать их в расчетах заказов.


2. Пользовательские функции
validate_order_items(JSON)

Назначение:
Проверка возможности создания заказа.

Что проверяет:

1. Существование каждого товара

2. Достаточность количества на складе

Где используется:
В процедуре create_order до создания заказа.

Почему это функция:
Позволяет переиспользовать логику и гарантировать целостность данных независимо от источника вызова.

get_product_final_price(product_id) 

Назначение:
Расчет итоговой цены товара с учетом всех действующих скидок.

Особенности:

1. Использует LEFT JOIN для учета отсутствия скидок

2. Применяет максимальную скидку при наличии нескольких

Для чего:
Цена всегда рассчитывается динамически и корректно, без дублирования логики в запросах.

is_order_final(order_id)

Назначение:
Определение, находится ли заказ в финальном состоянии.

Используется в:

update_order_status

Для чего:
Четко разделяет бизнес-логику и позволяет централизованно управлять правилами перехода статусов.

3. Триггеры
tr_order_items_after_insert

Срабатывает:
AFTER INSERT ON Order_Items

Что делает:
Автоматически уменьшает остаток товара на складе.

Для чего:
Исключает ручное управление складом
Гарантирует консистентность данных даже при прямых INSERT-запросах

tr_orders_before_update

Срабатывает:
BEFORE UPDATE ON Orders

Что делает:
Автоматически обновляет дату изменения заказа.

Для чего:
Обеспечивает корректный аудит изменений без необходимости контролировать это в коде приложения.

4. Использованные техники оптимизации
Индексация

Созданы индексы по:

1. внешним ключам (customer_id, order_id, cart_id)

2. часто используемым полям (email, category_id)

Влияние:

1. Ускоряет JOIN-операции

2. Существенно снижает время выполнения аналитических запросов

Представления

Используются для:

1. отчетов по заказам (v_orders_summary)

2. аналитики продаж (v_top_products)

Влияние:

1. Упрощает SQL-запросы

2. Повышает читаемость и повторное использование логики

3. Снижает вероятность ошибок в аналитике

Используется для:

1. расчета топ-продаваемых товаров

Влияние:

1. Улучшает читаемость сложных запросов
